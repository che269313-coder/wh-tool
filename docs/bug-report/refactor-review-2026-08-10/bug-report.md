# Bug 诊断胶囊：重构全量审核问题闭环

| 栏位 | 内容 |
| --- | --- |
| **1. 现象** | 规则解析层测试虽通过，但应用载荷装配会双计造伤修正；若干技能缺阶段门、缺通用效果或写入错误攻防方向；身份生成器不能把已翻译名提升为官网匹配；部分星际战士武器数据仍有明确提取错误。 |
| **2. 证据** | `docs/audit/refactor-full-review.md` 的 R1–R2、G1–G5；本地逆向检查确认 `app.js` 同时累加 `sourceRules.woundModifier` 与已含同一来源的 `sharedJoinedRules.woundModifier`，`effects.js` 将暴击阈值同时写入 attack/defend，生成器多处绕过 `phaseFor`。可检索数据卡表格确认等离子手枪 AP、地狱轰击者武器和四张卡的近战武器缺失。 |
| **3. 问题假设或根因** | 确认根因是 resolver 单测未覆盖 app 载荷装配；阶段语义从自然语言推导时没有先去除词内空格，且直接 `effects.push` 绕过统一 `add`；身份生成器把“译文存在”误当成“不需要再匹配官网”；一次性提取数据没有对混合模型与跨行武器表做结构化复核。 |
| **4. 诊断策略** | 分别在规则、架构和数据卡校验器增加最小失败断言；身份映射与阶段规则用生成产物验证；载荷装配抽取纯函数验证；数据修改只采用本地可检索 PDF 表格中的明确值。 |
| **5. 超时策略** | 若某项无法由现有原文或确定性运行路径证明，则不改运行数据，记录为驳回/待人工核对；不以推测值让测试变绿。 |
| **6. 预警策略** | 若修复需要技能名特判进入核心、增加三层以上 fallback、或导致其他阵营回归，则停止局部打补丁并回到通用语义接口。 |
| **7. 用户可见交互修正** | 造伤加成不再翻倍；射击/近战限定技能不会跨阶段泄漏；攻击方暴击技能不会反向增益敌人；缺失武器和混合模型属性可正确进入计算器。 |
| **8. 验收** | Red：新增断言分别复现 R1–R2、G1–G5、普通 FNP 致命伤、武艺大师单独部署、扭颅疫病方向、条件性灵能 FNP、武器范围 A 修正、剑卫防御重投及明确数据缺口。Green：五个 `validate-*.mjs` 全绿，生成器幂等，`git diff --check` 通过。 |

## 审核意见分类

- **确认并修复**：R1、R2、G1–G5；普通 FNP 未覆盖致命伤害；武艺大师错误要求 joined；D1–D4；D6 混合模型档案；灵能 FNP 过度应用；目标歼灭武器范围；剑卫特殊保护重投；瓦雷利安关键词。该次审核曾依据十版 PDF 把扭颅疫病判定为“错误限近战”，后来已由 11 版勘误 `ERRATA-2026-08-09-001` 明确取代。
- **报告过时/不按建议修改**：D5 裁决士。数据卡标量保持 `invulnerableSave: 0`，近战 4++ 已由 `invulnerable-save phase: melee` 正确表达；改成静态 4 会污染远程阶段。
- **保留显式失败而非 fallback**：禁军新增规则缺身份时抛错是稳定 ID 完整性门禁，不应改成可选降级；仅复用通用 `applyCatalog` 消除重复实现。
- **非当前伤害计算范围**：部署、移动、CP、震慑和单颗骰改为 6 等尚无中立计算语义的展示型规则，不伪装成已计算。精准目标分配已随通用武器能力进入公共分配层。
