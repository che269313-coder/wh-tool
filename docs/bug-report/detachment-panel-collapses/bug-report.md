# Bug 诊断胶囊：勾选分遣队后面板自动收起

| 栏位 | 内容 |
|------|------|
| **1. 现象** | 展开计算器中的“分遣队”，勾选任一分遣队后面板立即收起；期望面板保持展开，便于继续勾选或阅读规则。 |
| **2. 证据** | `#calculatorDetails` 的 `change` 监听器在每次选择变化后调用 `renderCalculatorDetails()`；该函数替换容器的全部 `innerHTML`，新建的 `.calculator-detachments` 没有 `open` 属性。 |
| **3. 根因** | 重绘前没有保存原 `<details>` 的展开状态，重绘后浏览器按默认关闭状态创建节点。 |
| **4. 诊断策略** | 逆向追踪 checkbox change → `updateCalculatorDraftFromControl` → `renderCalculatorDetails` → `innerHTML` 替换，并对照页面中显式使用 `open` 的其他 `<details>`。 |
| **5. 超时策略** | 若最小 DOM 单测无法复现，则改用浏览器端交互测试记录重绘前后 `details.open`。 |
| **6. 预警策略** | 若保存/恢复展开状态后仍收起，检查是否存在额外的 `toggle`/click 处理或第二次异步重绘。 |
| **7. 用户可见交互修正** | 勾选/取消分遣队后，已经展开的分遣队面板继续保持展开。 |
| **8. 验收** | 自动化测试模拟一个展开面板经过 `renderCalculatorDetails()` 重绘，断言新面板仍为展开；随后执行项目校验和浏览器手工验证。 |

## 五件套

- 报告人：用户在实际操作中发现。
- 复现：打开任一计算单位的分遣队面板，勾选一个选项；实际面板关闭，期望保持展开。
- 根因：整体重绘丢失原生 `<details>` 的瞬时 `open` 状态。
- 修复：重绘前按面板顺序捕获 `open`，重绘后恢复到对应的新节点。
- 验证：回归测试覆盖展开状态；运行现有架构/规则校验，并在页面中复测连续勾选。
