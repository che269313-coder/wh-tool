# 分遣队增强分配与计算页布局

## 症状

- 联合单位中的护卫也出现增强选择器，但增强只能分配给角色。
- 分遣队区域默认展开，且模拟结果位于大量单位/技能配置之后。
- 三个已支持阵营的分遣队生成物仍合并在一个文件里，单队重生成会改写其他队伍的产物。

## 最小复现

1. 导入含角色与护卫的联合单位并进入计算页。
2. 启用任一分遣队。
3. 观察角色和护卫都出现“增强”下拉框；运行模拟后需要越过全部单位详情才能看到结果。

## 预期

- 只有角色候选者出现增强选择器；多个角色各自独立分配。
- `owner` 增强只影响持有者，`unit` 增强按原文影响整个联合单位。
- 分遣队默认折叠；结果紧跟“本地模拟 1,000 次”按钮。
- 单队分遣队生成只写该队文件，不重写其他队伍。

## 根因假设与证据

- `calculatorDetachmentAssignmentTargets` 直接返回联合单位的全部军表成员，没有角色资格过滤。
- 分遣队外层使用普通 `section`，结果 DOM 写在 `calculatorDetails` 后。
- 生成器把全部阵营合并写入 `docs/rules/detachments.js`。

## 修复策略

1. 在纯军表上下文模块定义稳定的角色资格判断与目标筛选，UI 只消费结果。
2. 保留增强的 `owner/unit` 语义作用域；增加“多角色 + 护卫”回归用例。
3. 调整静态 DOM 顺序与 `details` 默认状态。
4. 分遣队按阵营生成、注册和加载，并增加单队生成隔离测试。

## 验收

- 护卫没有增强选择器，两个角色仍各有独立选择器。
- 持有者效果不泄漏，单位效果只归约一次并覆盖联合单位。
- 分遣队默认收起；模拟结果紧邻模拟按钮下方。
- 三队数量、稳定 ID、规则解析和全部既有验证通过。
