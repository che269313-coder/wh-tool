# Bug 诊断胶囊与修复记录：无声护卫作用对象

## 诊断胶囊

| 栏位 | 内容 |
| --- | --- |
| **1. 现象** | “无声护卫”只应让领导死亡寿衣终结者的角色模型获得“不知疼痛 4+”，死亡寿衣自身不得获得。 |
| **2. 证据** | 数据卡原文为“当有角色领导此单位时，该角色获得‘不知疼痛4+’”。当前生成器已产出 `leader-fnp`，应用层也有跨防守分组转移代码；但既有测试仅断言规则类型，没有验证最终角色组与护卫组的防御 payload。 |
| **3. 问题假设或根因** | 已确认当前工作树的数值方向正确，但“护卫规则授予领导角色”的分配逻辑内嵌在 `app.js`，没有纯函数契约与最终分组回归，容易在联合单位重构时再次反转。 |
| **4. 诊断策略** | 逆向追踪 `death-guard.js` → `effects.js` → `defenderEffectsFromUnit` → `buildDefenderGroups`；把跨组授予抽为中立纯函数并直接测试角色、护卫和未联合三种边界。 |
| **5. 超时策略** | 若角色身份无法从现有 `isLeader` 结构稳定判断，则停止增加名称匹配，转而要求联合单位导入层提供显式角色语义。 |
| **6. 预警策略** | 核心函数若出现“死亡寿衣”“无声护卫”或阵营 ID，说明修复退化为名称耦合，必须撤回。 |
| **7. 用户可见交互修正** | 联合单位中只有角色防御组显示并使用 4+ 不知疼痛；死亡寿衣护卫组保持自身原有防御。 |
| **8. 验收** | `validate-rules.mjs` 必须证明：角色获得普通及致命伤害 4+ FNP、护卫不获得、没有领导角色时无人获得；全量五组验证继续通过。 |

## 五件套

1. **报告人**：用户在 2026-08-09 复核死亡守卫规则时指出。
2. **复现步骤**：构造死亡寿衣护卫组，其效果含 `leaderFeelNoPain: 4`，再加入一个领导角色组；比较两个组的最终防御效果。
3. **根因分析**：规则解析已经正确；风险位于跨单位成员的最终效果分配缺少独立契约与行为测试。
4. **修复方案**：新增阵营无关的 `applyLeaderGrantedDefenses` 纯函数，由应用最终分组统一调用；不按技能名、单位名或阵营名判断。
5. **验证方式**：先观察缺少该函数的失败测试，再实现并运行规则、战斗、架构、数据卡和身份校验。
