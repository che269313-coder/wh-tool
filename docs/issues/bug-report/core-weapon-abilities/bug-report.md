# 通用武器能力未完整进入计算链

| 栏位 | 内容 |
| --- | --- |
| 现象 | 数据卡中的速射、热熔、爆炸、危险等通用武器能力只显示名称，没有改变攻击次数、伤害、合法武器或后续掷骰。 |
| 证据 | Git 历史中的 `11版核心规则简中.pdf` 第 79–85 页定义了 21 种通用武器能力；现有 `keyword-dictionary.js` 只产出连击、致命一击、毁灭伤害、双联、洪流和针对类 payload。 |
| 根因 | 旧适配器把武器词条直接压缩成少量外部计算器字段，没有中立的“武器能力 + 战斗上下文”归约层；旧审计又用未启用词条的相同 payload 对比随机结果，错误地把“数值接近”判为支持。 |
| 诊断策略 | 对照原始 PDF 的 24.03–24.38，逐项建立确定性解析、上下文归约和引擎测试；禁止按武器名或阵营名分支。 |
| 超时策略 | 若某项需要当前计算器完全不存在的阶段状态，先实现稳定语义、显式状态输入和合法性结果，再扩展引擎，不能退回仅显示文本。 |
| 预警策略 | 若新增阵营数据无需修改核心层却不能触发词条，说明词条解析或数据规范化仍有缺口；若同一状态在队伍规则和核心词条各自实现，说明出现重复坐标系。 |
| 用户可见修正 | 计算器提供半射程、移动、交战、冲锋、掩体和曲射等通用战斗状态；单发与精准提供武器级选择；危险会报告进攻方平均反噬伤害。 |
| 验收 | `validate-rules.mjs` 覆盖全部武器能力的稳定语义；`validate-combat.mjs` 覆盖危险、精准和灵能条件防御；全量验证与本地界面操作通过。 |
