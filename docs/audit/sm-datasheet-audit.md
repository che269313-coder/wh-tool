## 三、每类问题代表例与说明

### W1 水印字符残留(约 43 处,defaultEquipment 为主)
**代表例:**
1. P51 文崔斯连长 defaultEquipment `"群 爆弹手枪，不败者…"` — PDF 原文无"群"
2. P66 重装连长 defaultEquipment `"腐 精工重型爆弹步枪…"` — "腐"
3. P134 运输载具 defaultEquipment `"战 双联重型爆弹枪…"` — "战"
**说明:** 提取时把 PDF 水印"老湿腐战锤群 52110733"的单个字(老/湿/腐/战/群/孤立锤)拼进了 defaultEquipment 开头,部分也进入 abilities 正文(P47"锤在这个阶段结束时")和武器名(P112"老 动力拳")。字符本身无数据含义,但会污染装备匹配(如按名称匹配武器时会失败),必须剔除。

### W2 武器 abilities 杂散数字前缀(约 100 处,系统性)
**代表例:**
1. P48 卡尔加近战"奥特拉玛之拳" abilities `["3 双联"]` — PDF 仅"双联"
2. P50 西卡留斯"塔拉萨风暴之剑(重击)" abilities `["0 毁灭伤害"]` — PDF 仅"毁灭伤害"
3. P141 冲击者"贝立凯图导弹阵列(破片)" abilities `["7 0 爆炸"]` — PDF 仅"爆炸"
**说明:** 全文件 weapons[].abilities 有约 100 个条目以"数字+空格"开头(3/0/1/7/5/2),P90/P141/P147 甚至出现双重前缀("3 3 手枪"、"7 0 爆炸")。来源是 PDF 表格跨行提取时把上一行数字带入。这些数字不属于任何武器技能,且会被计算器当作技能名解析(如"3 手枪"会被当成未知技能),影响反步兵4+/反载具2+ 等解析。

### W3 特殊保护被吞 / invulnerableSave 错值(5 张卡)
**代表例:**
1. P87 裁决士 inv=0,PDF 技能首行"特殊保护：本模型对抗近战攻击时拥有4+特殊保护"
2. P94 剑卫老兵小队 inv=0,PDF"特殊保护：本单位模型拥有4+特殊保护"
3. P107/P108 终结者(突击终结者小队/终结者小队)inv=0,PDF 均有"本单位模型拥有4+特殊保护"
**说明:** 与历史 bug"恢复星际战士英雄4+特殊保护"同源——提取时把位于技能区第一行的"特殊保护"行整体吞掉,invulnerableSave 落为 0,导致这些单位在计算器中完全丧失 4+ 特殊保护(P107/P108 是 5 人终结者,影响重大)。另 P53 奥特拉马守护者 inv=5 属推测值(属性表无 ISV 列)。

### W4 武器整条缺失(6 张卡 7 条)
**代表例:**
1. P74 智库缺"惩击(巫火)/(聚焦)"两条灵能武器(P76 终结者智库同)
2. P65 连长缺"等离子手枪(标准/过载)"两条(P69 跳跃背包连长、P80 跳跃背包牧师同)
3. P121 机甲(不屈型战术机甲)缺近战"不屈铁拳"
**说明:** 均发生在"默认装备栏提到该武器(如 defaultEquipment 含"惩击"),但武器表未提取"的情况——即武器表行被整行丢弃,但装备栏还引用着它,计算时会出现"装备了不存在的武器"。

### W5 武器数值/结构错误(3 处)
**代表例:**
1. P90 仲裁者小队"阿斯塔特榴弹发射器(穿甲)" ap=**0**,PDF 为 **-2**(提取跨行错位)
2. P136 救赎者型兰德掠袭者"烈火风暴炮" attacks=**"3"**,PDF 为 **"D6+3"**(PDF 表内 D6+3 被换行拆成"D6+"/"3",提取只取到 3)
3. P90 榴弹发射器 selectionGroup 被塞入"爆弹手枪/爆弹步枪/喷火手枪"3 个伪形态(PDF 中为独立武器行)
**说明:** 这两处数值错误会直接改变结算(穿甲榴弹 AP-2 打成 0;烈火风暴炮 D6+3 打成 3 发)。

### W6 name 用了 PDF 页分类标题(11 张卡)
**代表例:**
1. P88 name"战术护甲步兵" → 实际单位"连队英雄"
2. P107 name"终结者" → 实际单位"突击终结者小队"
3. P150 name"工事" → 实际单位"落锤堡"
