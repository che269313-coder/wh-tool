# 审核机制

本文只描述如何审核当前架构下的资料、规则和代码。变更过程与历史结论通过 Git、`docs/plans/` 和具体 bug 报告查看，不写入本文。

## 审核原则

审核结论必须能回答三件事：规则是否忠于当前来源、效果是否通过稳定语义进入计算、变更是否被限制在正确队伍和正确层级。

不要只检查页面“看起来能用”。每项可计算规则都要沿以下链路追踪：

```text
原始资料 → 稳定规则 ID → effect + 条件/作用域 → resolver → payload → engine → 结果/UI
```

## 1. 变更面审核

先查看 `git status --short` 和 diff 文件列表。

纯队伍资料更新应主要落在该队目录、该队规则包、该队分遣队包和该队测试。若出现以下文件，必须要求单独的架构理由和跨队回归：

- `docs/engine.js`
- `docs/rules/effects.js`
- `docs/rules/effect-schema.js`
- `docs/rules/resolver.js`
- `docs/rules/payload-schema.js`
- `docs/app.js` 的全局计算流程

新增队伍对 `factions.js` 和 `index.html` 的修改只能是注册/加载，不得夹带规则行为。

## 2. 来源与数据完整性

- 原始资料位于 `docs/data/<队伍>/`；PDF 没有进入 Git。
- 可检索文本与 PDF/当前勘误逐条对应，页码和跨页表格可追溯。
- JSON 符合模板，单位数、模型档案、武器档案和技能数没有静默缺失。
- 程序数据是当前版本；版本差异记录在 `docs/errata/`，运行时没有补丁叠加代码。
- 分遣队、计谋和增强保留完整原文、点数和限制。

## 3. 身份与解耦

- 阵营、数据卡、规则、分遣队、计谋和增强都有稳定 ID。
- 行为以 ID、effect 类型和 schema 字段为契约，不以中文名、英文名或模糊包含匹配为契约。
- 改显示名/别名后，存档键和计算结果不变。
- 生成文件按队伍隔离；单队生成前后，其他队伍文件哈希相同。
- 当前队伍 resolver 查询不会返回其他队伍规则。

## 4. 规则语义审核

逐条检查：

- `phase`：远程、近战或双方；例如只允许近战的造伤重投不能影响远程武器。
- `direction`：进攻增益与防守减益不能反向或重复应用。
- `target`：模型、持有者、所在单位、敌方单位、具体武器类型是否准确。
- `effectScope`：增强 `owner` 只影响持有角色；`unit` 才能共享给联合单位，而且只归约一次。
- `requiresJoined`、关键词和武器限制：条件不满足时解析结果为空。
- 叠加顺序：命中/造伤修正、重投、暴击、致命一击、伤害减免与最低伤害符合规则步骤。
- 无法由现有计算器准确表达的规则只展示原文，不用近似值冒充。

联合单位至少构造“角色 A + 角色 B + 护卫”测试：A 的 `owner` 增强不得影响 B 或护卫；A 的 `unit` 增强按原文影响整个联合单位；护卫不能分配增强。

## 5. UI 与军表状态审核

- 未导入军表时分遣队默认关闭；导入后读取该军表预设，玩家仍可调整。
- 分遣队区域默认折叠，展开后才显示选择、增强和完整规则。
- 模拟结果紧跟 1,000 次模拟按钮，位于长技能详情之前。
- 只有角色显示增强选择器；多个角色分别保存增强，不按单位名共用状态。
- 进攻/防守双方同阵营、同名单位仍按军表实例隔离。
- 技能造成命中修正时，命中重投框使用修正后的有效成功阈值；不能按技能名特判颜色。
- 武器多选一档案允许全不选；手枪档案不得迫使模型只能选手枪组。
- 通用武器条件按关键词分组，所有选项文案标明触发它的关键词。

## 6. 回归矩阵

至少覆盖：

| 维度 | 用例 |
| --- | --- |
| 队伍 | 帝皇禁军、星际战士、死亡守卫各一项可计算规则 |
| 阶段 | 同一效果在正确阶段生效、错误阶段为空 |
| 方向 | 进攻修正、防守修正、双方组合 |
| 联合单位 | 单角色、双角色、角色 + 护卫、无角色 |
| 增强 | `owner`、`unit`、未装备、切换分遣队后失效 |
| 军表实例 | 同阵营内战、同名单位、两边不同分遣队 |
| 武器 | 通用关键词、近战/远程限制、手枪组、多选一、额外攻击 |
| 状态 | 未导入默认关闭、导入预设、玩家重新分配 |
| 隔离 | 单队生成不改其他队文件；无跨队规则泄漏 |

## 7. 自动门禁

```powershell
node tools/generate-faction-identities.mjs
node tools/generate-detachment-rules.mjs
node tools/validate-datasheets.mjs
node tools/validate-rules.mjs
node tools/validate-detachments.mjs
node tools/validate-combat.mjs
node tools/validate-architecture.mjs
node tools/validate-40k-app.mjs
node --check docs/app.js
node --check docs/engine.js
```

生成器运行后必须再次运行验证。任何失败都要修复根因；不得降低期望数量、放宽 schema 或删除断言来让门禁变绿。

## 8. 审核输出

审核报告只记录当前变更的：

1. 阻塞问题，包含文件、规则 ID、来源证据和可复现步骤。
2. 非阻塞风险，说明影响范围和建议测试。
3. 已验证项与实际运行的命令。
4. 仍为仅供查阅的规则及其既有决议链接；已决议项目不重复要求实现。
